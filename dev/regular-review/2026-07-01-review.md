# Code Review 计划 — 2026-07-01

## 一、正确性 Bug

### 1. 邮箱配置假默认值绕过"未配置"检测
- **原因**：给一个原本必填的邮箱字段加上了占位默认值。
- **影响**：配置不完整时程序不再报"未配置"，而是悄悄用假地址尝试发信，导致邮件发送失败且报错信息令人困惑。
- **方案**：恢复该字段为必填，让"未配置"状态在调用方明确可辨。

### 2. MCQ 页面跳过配置功能在实际使用中完全不生效
- **原因**：新增的按科目查页面配置的逻辑依赖于原始文件名，但实际传入的是临时文件的随机文件名。
- **影响**：所有科目都会退回硬编码的默认跳过页设置，本次新增的按科目配置形同虚设。
- **方案**：让页面配置查找基于用户上传时的原始文件名，而不是临时文件路径。

### 3. 试卷分栏识别中单字符边界可能误判
- **原因**：新增的单字符题号识别逻辑与另一套独立构建的字符映射表存在字节冲突的可能。
- **影响**：某些子题标记可能被误认成主题号边界，导致对应题目的裁剪区域出错。
- **方案**：为单字符判断增加更可靠的上下文校验，而非仅依赖字符映射表解码结果。

### 4. 页码区域识别阈值放宽后与正文区域重叠
- **原因**：为兼容个别试卷调宽了页码区域的纵向判定范围，但该范围现已越过正文起始位置。
- **影响**：正文顶部的真实题号可能被误当成页码而被排除或污染字符映射表。
- **方案**：改用更贴近实际版式的判定依据，而非单纯放宽固定像素阈值。

### 5. 手动补录答案时空输入被误判为有效答案
- **原因**：判断输入是否为有效选项时使用了字符串包含逻辑，空字符串在这种写法下会被误判为匹配。
- **影响**：用户还未填写时，题目就会被提前标记为"已作答"，影响状态显示和判分时机。
- **方案**：改为判断输入是否为非空且属于合法选项集合。

## 二、冗余逻辑

### 6. 新增页面配置的加载方式与已有配置加载模式重复且更弱
- **原因**：新增配置类型没有复用项目里已有的配置加载与校验方式，而是自己另写了一套。
- **影响**：两套逻辑分别维护，且新的一套在解析出错时行为更宽松，容易掩盖配置文件本身的问题。
- **方案**：让新配置复用已有的加载校验方式，保持全项目一致的错误处理方式。

### 7. 同一文件中存在多处重复的文件名解析逻辑
- **原因**：文件名格式的解析规则在项目里被分别独立实现了多次。
- **影响**：文件名格式一旦调整，容易只改了一处而漏掉其余几处，导致解析结果不一致。
- **方案**：把文件名解析收敛到一处公用逻辑，其余地方直接复用。

### 8. 页面配置文件中存在大量重复条目
- **原因**：配置文件为每个科目的每个分卷都单独写了一份，其中很多条目内容完全相同。
- **影响**：新增或调整某类通用规则时需要同时修改多处重复内容，容易遗漏。
- **方案**：将相同的配置提炼为科目级别的默认值，仅对有差异的分卷单独覆盖。

### 9. 未使用的参数与不一致的默认值同时存在
- **原因**：预留了一个从未被调用方使用的参数，且其内置默认值与配置文件里的默认值并不一致。
- **影响**：增加了阅读和维护该函数时的困惑，且两处默认值不同步的风险持续存在。
- **方案**：去掉未使用的参数，将默认值统一到一个来源。

### 10. 存在一处对结果无影响的死赋值
- **原因**：为其中一种试卷类型赋了一个值，但该值在对应分支里从未被实际使用。
- **影响**：容易让阅读者误以为这个值在两种流程里都起作用，增加理解成本。
- **方案**：移除该分支下这一多余的赋值。
